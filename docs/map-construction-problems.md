# 建图问题归因（50 样本，对齐后）

> 2026-08-08 · 来源：`cogmap-casebycase.md`、`cogmap-issues.md`、`cogmap-direct-metrics.md`、`failure-case-analysis.md`。

## 0. 分层方式

按建图阶段把问题分成 5 层：计数、锚定、相对布局、高度、跨视图。每层给出证据、影响的 QA 类型、已有尝试、可选修法。

## 1. 计数层（最严重）

- 漏实例率 36~42%（4 个 arm），多实例率 0.8~4.3%。
- `chair` 是绝对大头：每个 arm 漏 45~51 个，4 个 arm 合计约 190；`table`、`ceiling light`、`monitor` 其次。
- 2-stage 实验证明摆位不是问题：摆位遵守计数 96.2%，但计数阶段本身 chair 精确命中 4/12、stool 1/8。
- 根因：VLM 从视频数不清高频多实例类别，不是“画图机制”问题。
- 影响：A1 与 C7 同源；rel_distance 里漏画会直接改变最近邻。
- 方向：外部检测器计数（E4）；同时补“GT 全场景 bbox vs 视频可见实例”口径，避免冤枉模型。

## 2. 锚定层（原点 / 朝向）

- 对齐平移中位约 4 格；yaw 中位 baseline 17.3°，三视图约 0°：模型地图与 GT 的差异主要是原点平移，不是旋转。
- 旧算法 4 个 arm 共报 86 处“镜像=是”（每 arm 19~26），且标签与坐标不一致：它标了镜像但实际用的是纯旋转。
- 修正后：真正应用镜像 48 处，其中 30 处有 x 顺序证据支持（每 arm 9/7/10/4），18 处仅因 RMSE 明显改善但证据未确认；其余不再算镜像。
- 共同匹配实例只有 2 个的样本（10~15/arm）现在用两点向量解 yaw，不再退化成仅平移；镜像仍按 x 顺序证据判定。
- 影响：不先对齐，绝对坐标完全不可比；FRONT/SIDE 的 x/y 也没法直接比。
- 方向：建图时先锚定场景原点 / 第一帧朝向 / 房间边界（E2 锚点版），一个改动同时压原点平移、镜像、尺度三类误差。

## 2.5 物体数量 / 尺寸效应（已验证，2026-08-10）

- 物体越多，漏画越严重：GT 实例数 1-2 个时漏画率 0%，3-5 个约 1%，6-10 个 32~44%，>10 个 75~77%（三个 arm 一致）。
- 小物体放位更差（尺度+z 补偿后 TOP ≤2 可接受率）：threeview 小物体 72% vs 大物体 97%；baseline 81% vs 89%；3-pass 86% vs 91%。
- 含义：漏画不只是“看不到”，而是多实例/小目标场景里 VLM 数不清、放不准；小目标定位需要外部检测器（E4）或更细的视频采样。

## 3. 相对布局 / 尺度层

- 对偶距离错题 42~45/50；紧邻对准确率 20~54%。
- 重复出错类别对：door-window、stove-table、refrigerator-stove、table-tv。
- 补偿后（尺度+z）仍超差(>2)的物体集中在：tv、lamp、table、stool、microwave、bed、chair；tv 在 threeview/3-pass 的 TOP/FRONT 反复错，lamp 在 threeview 的 TOP/SIDE，table 在多个 arm 的 TOP/SIDE。这些是单物体放错位置，不是全局尺度/z 能解释的。
- 尺度中位数 0.86~1.12：地图系统性压缩或膨胀，没有尺度锚。
- 方向精确 33~40%，±1 容差 73~100%（三视图为 100%，但分母小，别当强结论）。
- 影响：rel_distance、rel_direction 直接依赖这一层。
- 方向：用已知尺寸物体标定 grid→米（E3）；锚点版跑完后重测，不要把绝对 MAE 当唯一指标。

## 4. 高度层

- z 平均误差：threeview +1.19 格、2-stage +0.90 格、3-pass +0.43 格；偏高样本占比 52~71%。
- 高度排序准确率 75.8~89.4%：顺序大体对，但绝对高度系统性偏高。
- 影响：abs_distance 不依赖 z，但 height/appearance 类扩展题型会受影响。
- 方向：floor=0 锚 + 常见物体高度先验（门约 2m），即 E3 的高度版。

## 5. 跨视图层

- C7 跨视图漏画 ≈ A1 漏实例（39~42%），不是独立新问题。
- C6 冲突率约 0，是因为只检查“三个视图都画了”的实例：漏画样本根本没进冲突检查，指标偏乐观。
- 3-pass 强制数量一致后，地图没有更好（单次 vs 3-pass 对齐后 MAE≈0.9 格）。

## 6. 对齐技术评估

已实现（2026-08-10，不重跑实验）：

1. 实例级对齐：类别内按最近距离匹配实例，用匹配到的实例点直接解 Kabsch，不再用类别质心，漏画/多画不再拉偏质心。
2. 2 点样本解 yaw：共同匹配实例 =2 时，用两点向量解旋转角，不再退化成“仅平移”；镜像仍按 x 顺序证据判定。
3. 仍不拟合尺度与 z 平移：尺度中位数、z 偏置继续作为建图错误报告，不被对齐吸收。
4. 重新生成了 cogmap-casebycase.md / cogmap-issues.md / cogmap-direct-metrics.md。
   当前数字：RMSE 中位 baseline 1.08、threeview 1.15、3-pass 1.08、2-stage 1.01；镜像应用 17/10/14/7，证据支持 9/8/8/4；2 点样本 10/10/11/15。

仍未解决的结构性弱点：

1. 实例身份错位仍测不出来（baseline/threeview 实例错位率是 nan），需要更细的联合匹配。
2. 跨视图实例匹配依赖模型遵守 top.x==front.x / top.y==side.y；违例样本会标“未匹配”，不能被静默对齐掉。
3. 相机朝向先验需要从原始数据集拿 camera pose，本地 meta 没有，暂缓。

后续可选：把类别内最近邻匹配升级为 Hungarian 联合匹配，进一步测实例身份错位。

## 7. 优先级建议

1. 计数：E4 外部检测器，或先修正“GT 全场景 vs 视频可见”口径。
2. 锚定 + 尺度：E2 锚点版，一个改动覆盖原点平移、镜像、尺度三类系统性误差。
3. 高度：E3 的 floor=0 + 高度先验。
4. 对齐技术：最后做，除非怀疑 Procrustes 假镜像在误导当前结论。
