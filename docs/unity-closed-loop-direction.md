# Unity 空间表示 + 相机位姿重放闭环（新方向）

> 2026-07-31 · 方向切换交接文档

## 1. 背景

项目目标不变：提升 VLM 在 VSI-Bench 这类空间 QA 上的表现。

三视图认知图路线已验证到瓶颈：
- 纯 prompting 建图可以达到 100% 物体召回（task-aware），但坐标精度不足
- 2D 可视化（PNG）与文本事实注入无法稳定提升回答准确率
- 绝对距离估计接近 0% MRA

结论：与其继续在 2D/文本中间表示上打磨，不如切换到精确可控的 3D 模拟环境。Unity 可以承载空间表示，并提供相机位姿模拟和真实渲染，构成可验证的闭环。

## 2. 闭环设计（v0 草案）

```
原始视频 / VSI-Bench 观测
        │
        ▼
[1] 构建 Unity 空间表示（场景布局、物体、几何）
        │
        ▼
[2] 恢复相机位姿（数据集真实位姿 or 估计）
        │
        ▼
[3] Unity 中重放相机路径，渲染观测帧
        │
        ▼
[4] 反馈验证：渲染 vs 原始观测（像素/几何/物体）
        │
        ▼
[5] 迭代表示（修正布局/位姿/遮挡）
        │
        ▼
[6] 用最终表示/渲染回答 VSI-Bench QA（复用现有 harness）
```

## 3. 设计要点

### 3.1 空间表示怎么进 Unity

候选（需对齐）：
- A. VLM 输出布局 JSON → 转 Unity 场景（延续 task-aware 建图，但换成 3D）
- B. 从视频做 3D 重建（3DGS / NeRF / DUSt3R / 深度估计）→ 导入 Unity
- C. 直接用数据集真值（ScanNet 等）做 Oracle / 上界实验

### 3.2 相机位姿

- 优先用数据集提供的真实位姿（ScanNet / ScanNet++ / ARKitScenes 通常有）
- 若没有，用 COLMAP / SLAM / DUSt3R 估计
- 验证“重走”是否准确：渲染帧与原始帧对齐程度

### 3.3 反馈信号

- 像素级：渲染帧 vs 原帧（LPIPS / SSIM / 关键区域误差）
- 几何级：物体位置/朝向/尺寸误差
- 任务级：用表示回答 VSI-Bench QA 的准确率变化
- VLM 级：让 VLM 对比渲染与原始观测并指出不一致（可解释）

### 3.4 Unity 工程形态

- 最小方案：Unity Editor 批处理模式离线渲染，Python 驱动
- 后续可选：Unity + Python 控制（如 Unity ML-Agents / ROS 桥接），或渲染服务器

## 4. 成功标准（初版）

1. 至少 1 个 VSI-Bench 场景跑通“视频 → Unity 场景 → 重放位姿 → 渲染 → 反馈 → 修正”全流程
2. 渲染帧与原始视频帧的定性对比可用（对齐相机后画面结构一致）
3. 在 50 样本子集上有可量化的 QA 结果，并对比三视图基线
4. 迭代反馈能可复现地改进空间表示或 QA 结果

## 5. 待确认问题

核心三个：
1. 场景表示生成方式：VLM 输出 / 3D 重建 / 数据集真值
2. 相机位姿来源：数据集真实位姿 or 估计位姿
3. 反馈信号粒度：像素 / 几何 / QA / VLM 自评
